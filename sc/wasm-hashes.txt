# Reproducible build hashes for the Forepay advance contract (#14).
#
# ONE ROW PER HOST TRIPLE, and only rows something actually verifies.
#
# Wasm is byte-identical **within** a host triple and toolchain, and **not across them**:
# the linker orders read-only data symbols differently per host, which shifts pointer
# constants. Section sizes stay identical, which makes it look tantalisingly close to
# reproducible and sends you hunting for a bug that is not there. Sterun lost days to
# exactly this, with a CI check that could never pass.
#
# So: a row is recorded only when something checks it. The linux row is rebuilt and
# compared by CI on every push. The macOS row is NOT checked by anything — CI has no
# macOS runner — so it is kept below the line as developer reference, not as evidence.
#
# The hash that matters for deployment is neither of these: it is the one the release
# workflow produces, because StellarExpert matches the on-chain wasm against the attested
# artifact. See docs/deployments.md.
